We can use the regular operations to build up expressions describing languages, which are called regular expressions. 
$$
(0 \cup 1)0^{\star }
$$
The value of a regular operation is a language.
We get this result by dissecting the expression into its parts. First, the symbols 0 and 1 are shorthand for the sets $\{ 0 \}$ and $\{ 1 \}$. So $(0\cup 1)$ means $(\{ 0 \} \cup \{  1 \})$. 
The value of this part is the language $\{ 0,1 \}$. The part $0^{*}$ means ${0}^{*}$, and its value is the language consisting of all strings containing any number of 0s. Second, like the $\times$ symbol in algebra, the concatenation symbol $\circ$.
<span style="color:	#87CEEB">Example</span> 
 Another example of a regular expression is:
 $$
(0 \cup 1)^{*}
$$
It starts with the language $(0 \cup 1)$ and applies the $\star$ operation. 
The value of this expression is the language consisting of all possible strings of 0s and 1s. If $\sum = \{ 0,1 \}$, we can write $\sum$ as shorthand for the regular expression $\sum$ describes the languages consisting of all strings over that alphabet. Similarly, $\sum ^{*}1$ is the language that contains all strings that end in a $1$. The language $\left( 0\sum ^{*} \right) \cup \left( \sum ^{*}1 \right)$ consists of all strings that start with a 0 or end with a 1.

# Formal definition of a regular expression
>[!note] Definition
>Say that $R$ is a **regular expression** if R is
>1.-  $a$ for some a in the alphabet $\sum$,
>2.- $\epsilon$,
>3.- $\emptyset$,
>4.- $(R_{1} \cup R_{2})$, where $R_{1}$ and $R_{2}$ are regular expressions,
>5.- $(R_{1} \circ R_{2})$, where $R_{1}$, and $R_{2}$ are regular expressions, or
>6.- $(R_{1}^{*})$, where $R_{1}$ is a regular expression.
>In items $1$ and $2$, the regular expressions $a$ and $\epsilon$ represent the languages $\{ a \}$ and $\{ \epsilon \}$, respectively. In item 3, the regular expression $\emptyset$ represents the empty languages obtained by taking the union or concatenation of the languages $R_{1}$ and $R_{2}$, or the star of the language $R_{1}$, respectively.

Don't confuse, the expression $\epsilon$ represents the language containing a single string, the -namely, the empty string- whereas $\emptyset$ represents the language that does not contain any strings..
A definition of this type is not circular, is **inductive definition**.
For convenience, we let $R^{+}$ be shorthand for $RR^{*}$. In other words, whereas $R^{*}$ has all strings that are 0 or more concatenations of strings from $R$, the language $R^{+}$ has all strings that are 1 or more concatenations of strings from $R$. So 
In simple words, $R^{+}$ is $R^{*}$ but with no epsilon.
In addition, we let $R^{k}$ be shorthand for the concatenation of $k$ $R's$ with each other. When we want to distinguish between a regular expression $R$ and the language that it describes, we write $L(R)$ to be the language of $R$.
In the book there are exercises. 
If we let $R$ be any regular expression, we have the following identities. They are good tests of whether you understand the definition.
$R \cup \emptyset = R$.
Adding the empty language to any other language will not change it. 
$R \circ \epsilon = R$.
Joining the empty string to any string will not change it.
>[!warning]  Be careful
>$R \cup \epsilon$ may not equal $R$.
>For example, if $R=0$, then $L(R) = \{ 0 \}$ but $L(R\cup \epsilon) = \{ 0,\epsilon \}$.
>$R \circ \emptyset$ may not equal $R$.
>For example, if $R=0$, then $L(R) = \{ 0 \}$ but $L(R \circ \emptyset) = \emptyset$.

Regular expressions are useful to design compilers for programming languages. 
**tokens**: elemental objects in a programming language.
Once the syntax of a programming language has been described with a regular expression in terms of its tokens, automatic systems can generate the **lexical analyzer**, the part of a compiler that initially processes the input program.
# Equivalence with Automata
Any regular expression can be converted into a finite automaton that recognizes the language it describes, and vice versa.

>A language is regular if and only if some regular expression describes it.

Let's define for the prove that a GNFA is similar to a nondeterministic finite automaton except for the transition function, which has the form:
$$
\delta:(Q -\{ q_{accept} \}) \times (Q - \{ q_{start} \}) \to \mathcal{R}
$$
the symbol $\mathcal{R}$ is the collection of all regular expressions over the alphabet. If $\delta (q_{i}, q_{j}) = R$, the arrow from state $q_{i}$ to state $q_{j}$ has the regular expression $R$ as its label. The domain of the transition function is $(Q -\{ q_{accept} \}) \times (Q - \{ q_{start} \})$ because an arrow connects every other state, except that no arrows are coming from $q_{accept}$ or going to $q_{start}$.
>[!note] Definition of a GNFA
>A generalized nondeterministic finite automaton is a $5-$tuple, $Q,\sum,\delta, q_{start}, q_{accept}$, where
>1. Q is the finite set of states,
>2. $\sum$ is the input alphabet,
>3. $\delta:(Q -\{ q_{accept} \}) \times (Q - \{ q_{start} \}) \to \mathcal{R}$ is the transition function
>4. $q_{start}$ and $q_{accept}$ are the start state, and the accept state.

A GNFA accepts a string $w$ in $\sum ^{*}$ if $w = w_{1}w_{2}\dots w_{k}$, where each $w_{i}$ is in $\sum ^{*}$ and a sequence of states $q_{0},q_{1},\dots,q_{k}$ exists such that
1. $q_{0} = q_{start}$ is the start state
2. $q_{k} = q_{accept}$ is the accept state, and
3. for each $i$, we have $w_{i} \in L(R_{i})$, where $R_{i} = \delta(q_{i-1},q_{i});$ in other words, $R_{i}$ is the expression on the arrow from $q_{i-1}$ to $q_{i}$.
