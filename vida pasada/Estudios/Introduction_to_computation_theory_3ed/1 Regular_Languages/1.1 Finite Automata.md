# Formal definition of a finite automaton
We'll express de formal definition to rest ambiguity when working on problems. On this specific case, finite automaton consists on 5 elements. One of them id the **transition function** $\delta$ to define the rules for moving. If the finite automaton has an arrow from a state $x$ to a state $y$ labeled with the input symbol 1, that means that if the automaton is in state $x$ when it reads a $1$, it then moves to state $y$. We indicate that by $\delta(x,1) = y$. 
>[!note] Finite automaton
>It is a $5$-tuple $Q,\sum,\delta,q_{0},F$ where 
>1. $Q$ is a finite set called the **states**,
>2. $\sum$ is finite set called the **alphabet**
>3. $\delta: Q \times \sum \to Q$ is the **transition function**
>4. $q_{0} \in Q$ is the **start state**, and
>5. $F \subseteq Q$ is the **set of accept states**

In the figure 1.6 formally we describe:
$$
\begin{align}
Q = \{ q_{1},q_{2},q_{3} \} \\
\sum = \{ 0,1 \} \\
\delta \text{ is described as } \\
q_{1} \text{ is the start state, and } \\
F = \{ q_{2} \}
\end{align}
$$
If $A$ is the set of all strings that machine $M$ accepts, we say that $A$ is the **language of machine M** and write $L(M) = A$. We say that **M recognizes A** or that **M accepts A**.
A machine may accept several strings, but it always recognizes only one language. If the machine accepts no strings, it still recognizes one language namely, the empty language $\emptyset$.

Now, we are generalizing. It does not mean we'll get all i's, it means we can handle any i. Like i = 3, for example.
For each $A_{i}$ we give a finite automaton $B_{i}$, recognizing $A_{i}$.
We describe the machine $B_{i}$ formally as follows: $B_{i} = (Q_{i}, \sum, \delta_{i}, q_{0}, \{ q_{0} \}),$ where $Q_{i}$ is the set of $i$ states $\{ q_{0},q_{1},q_{2},\dots,q_{i-1} \}$, and we design the transition funciton $\delta_{i}$ so that for each $j$ if $B_{i}$ is in the state of $q_{j}$, the running sum is $j$, modulo $i$.
For each $q_{j}$ let:
$$
\begin{align}
\delta(q_{j},0)  & = q_{j}, \\
\delta(q_{j},1)  & = q_{k}, \text{ where } k = j+1\text{ modulo } i, \\
\delta(q_{j},2) &  = q_{k}, \text{ where } k = j+2 \text{ modulo } i, \text{ and } \\
\delta(q_{j},RESET) &  = q_{0}
\end{align}
$$

# Formal definition of computation
We need to do it men, don't cry.
We already have an informal idea of the way it computes, and we now formalize it mathematically.
Let $M = (Q,\sum,\delta,q_{0},F)$ be a finite automaton and let $w = w_{1}w_{2}\dots w_{n}$ be a string where each $w_{i}$ is a member of the alphabet $\sum$. Then $M$ **accepts** w if a sequence of states $r_{0},r_{1},\dots,r_{n}$ in $Q$ exists with three conditions:
1. $r_{0} = q_{0}$
2. $\delta(r_{i},w_{i+1} = r_{i+1})$, for $i = 0,\dots,n-1$ and
3. $r_{n} \in F$
Condition 1 says that the machine starts in the start state. Condition 2 says that the machine goes from state to state according to the transition function. Condition 3 says that the machine accepts its input if it ends up in an accept state. We say $M$ **recognizes language** $A$ if $A = \{ w | M \text{ accepts w} \}$

>A language is called a **regular language** if some finite automaton recognizes it.

# The regular operations
In the theory of computation, the objects are languages and the tools include operations specifically designed for manipulating them. By these operations we study the properties of the regular languages.
>[!note] Definition 1.23
>Let $A$ and $B$ be languages. We define the regular operations **union**, **concatenation** and **star** as follows:
>- Union: $A \cup B = \{  x | x \in A \text{ or } x \in B \}$
>-  Concatenation: $A \circ B = \{  xy | x \in A \text{ and } y \in B \}$.
>- Star: $A* = \{  x_{1}x_{2}\dots x_{k}  | k \geq 0\}$ and each $x_{i} \in A$.

The concatenation operation is a little trickier. It attaches a string from A in front of a string from B in all possible ways to get the strings in the new language.
The star is infinitive except on $\{ ,\{ \epsilon \} \}$
That is, the star operation is a unary operation instead of a binary operation. It works by attaching any number of strings in A together to get a string in the new language.
Because "any number" includes 0 as a possibility, the empty string $\epsilon$ is always a member of $A*$, no matter what $A$ is.
The star is all posible combinations, there is an example in the book, could be infinite if its not empty.
>[!tip] Closed objects
>A collection of objects is clsed under some operation (multiply or sum) if applying that operation to members of the collection returns an object still in the collection.

We show that the collection of regular languages is closed under all three of the regular operations.
The proofs are in the book.
>[!tip] Theorem 1.25
>The class of regular languages is closed under the union operation. In other words, if $A_{1}$ and $A_{2}$ are regular langauges, so is $A_{1} \cup A_{2}$.

>[!tip] Theorem 1.26 
>The class of regular languages is closed under the concatenation operation. In other words, if $A_{1}$ and $A_{2}$ are regular languages then so is $A_{1} \circ A_{2}$.
