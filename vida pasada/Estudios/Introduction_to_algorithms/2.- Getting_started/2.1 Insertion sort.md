# Insertion sort
This algorithm solves the sorting problem introduced in chapter 1 [[1.2 Algorithms_ as_a_technology#Efficiency]]
___
<span style="color:	#87CEEB">Input</span>: A sequence of $n$ numbers $\langle a_{1},a_{2},\dots,a_{n} \rangle$.
<span style="color:yellow">Output</span>: A permutation (reordering): $\langle a_{1}', a_{2}',\dots, a_{n}' \rangle$-
The numbers that we wish to sort are also known as the **keys**. Conceptually we are sorting a sequence, but the input comes to us in the form of an array with $n$ elements.

>[!warning] Pseudo code
>In pseudo code we try to catch the essence of the algorithm, not necessarily the software or the specifications of the practical algorithm.
>

The code is made in c++. and is in clions folder.
**Insertion sort** consists of sorting an small number of elements by choosing the card one by one and put it into the right place in your deck.
At all times, the cards held in the left hand are sorted, and these cards were originally the top cards of the pile on the table.
In code, we made this by an array $A[1..n]$ containing a sequence of length $n$. Let´s see this:
![[Insertion_Sort.png]]
The black block is the key. The shadow rectangle is the sorted array. So, we just need to put the key into the right place and after that move the key to the top of the pile of the array already sorted.
```cpp
1 for j = 2 to A.lenght
2 	key = A[j]
3 	// Insert A[j] into the sorted sequence A[1..j-1]
4	i = j-1
5	while i > 0 and A[i] > key
6		A[i+1] = A[i]
7		i = i-1
8	A[i + 1] = key
```

Remember that i is going to be global, and does not disappear when the loop is finished.
## Loop invariants and the correctness of insertion sort.

The index j indicated the "current card" being inserted into the hand, it's index j which is going to cover all the array. At the beginning of each iteration, the sub array consisting of elements $A[1..j-1]$ constitutes **the currently sorted hand** and the rest is the pile that's in the table.
In fact, elements $A[1..j-1]$ are the elements *originally* in positions 1 through $j-1$, but now in sorted order. We state these properties of $A[1..j-1]$ formally as a **loop invariant** (Literally a property that does not change neither before or after an iteration).
In this case:
The subarray $A[1..j-1]$ consists of the elements originally in $A[1..j-1]$, but in sorted order.
This, will help us to understand why an algorithm is correct. Some things about loop invariant.
**Initialization**: It is true prior to the first iteration of the loop.
**Maintenance**: If it is true before an iteration of the loop, it remains true before the next iteration.
**Termination:** When the loop terminates, the invariant fives us a useful property that helps show that the algorithm is correct.
When the first two properties hold, the loop invariant is true prior(before) to every iteration of the loop. Notice the similarity with mathematical induction except for the third condition.
Typically, we use the loop invariant along with the condition that caused the loop to terminate. We use this property to stop the "induction" when the loop terminates.
___
For insertion sort:
**Initialization:** We start by showing that the loop invariant holds before the first loop iteration, when $j = 2$. The subarray $A[1..j-1]$, therefore, consists of just $A[1]$, which is in fact the original element in $A[1]$. Moreover, this subarray is sorted (trivially), which shows that the loop invariant holds prior to the first iteration of the loop. 
**Maintenance**: Next, we tackle the second property: showing that each iteration maintains the loop invariant. Informally, the body of the **for** loop works by moving $A[j-1],A[j-2], A[j-3]$, and so on by one position to the right until it finds the correct position to insert the element $A[j]$. The subarray $A[1..j]$ then consists of the elements originally in $A[1..j]$, but in sorted order. Incrementing $j$ for the next iteration of the **for** loop then preserves the loop invariant.
(This is doing informal, but formally we need to state and show a loop invariant for the **while** loop).
**Termination**: The condition that terminates the **for** loop is that $j>A.length = n$. Because each iteration increases j by one, $j = n+1$.
Substituting $n+1$ for $j$ in the wording of loop invariant, we have that the subarray $a[1..n]$ consists of the elements originally in $A[1..n]$, but in sorted order. Observing that the subarray $A[1..n]$ is the entire array we conclude that the entire array is sorted. Hence, the algorithm is correct. ^2fd2a8

>[!warning]
>[[2.1 Insertion sort#^2fd2a8]] When is a **for** loop, the moment at which we check the loop invariant just prior to the first iteration is immediately after the initial assignment to the loop-counter variable and just before the first test in the loop header. In our case: this time is after assigning 2 to the variable $j$ but before the first test of whether $j\leq A.length$.
