## Resumen 
Taco Bell uses an arquitecture that allows them to handle more than 42 million of orders.

[[Example-Arquitecture of taco Bell (system)]]

The arquitectura is main based on events, it means when an event arise the system is enable and permits to do a certain task

An example of this is a costumer who wants to make an order, then he goes to taco bell, and order to his phone, after that the system make all recorrides, through an api gateway (application),event bridge, step fucnitons, and lambdas, to finally retrieve the output or validation to delivery aggregation.

The stepfucntions used in aws wait until some event fo trhgout it and make another function or trigger something.
This kind of arquitecture model real life, or real way of make an order.
The arquitecture of Taco bell is serverless and can scale as much as you want, because it gives you specifications on how much it cost, the robust of the system and possibly how to make that more scalable.
