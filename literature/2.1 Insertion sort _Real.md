#### Loop Invariant Statement

At the start of each iteration of the loop (for index $j$), the subarray $A[1..j-1]$ consists of elements that are all **not equal** to $v$.

#### 1. Initialization

**Goal:** Show the invariant is true before the first iteration ($j=1$).

- **Proof:** When $j=1$, the subarray $A[1..j-1]$ is $A[1..0]$. This is an empty subarray. An empty set of elements trivially contains no elements equal to $v$. Therefore, the invariant holds.
    

#### 2. Maintenance

**Goal:** Show that if the invariant is true before iteration $j$, it remains true before iteration $j+1$.

- **Proof:** Suppose the invariant is true for $j$ (meaning $v$ is not in $A[1..j-1]$).
    
    - The loop body checks `if A[j] == v`.
        
    - **Case 1 (Found):** If $A[j] == v$, the algorithm returns $j$ and terminates immediately. Correctness is ensured.
        
    - **Case 2 (Not Found):** If $A[j] \neq v$, the loop proceeds to increment $j$ to $j+1$.
        
    - Because we already knew $v$ wasn't in $A[1..j-1]$ (from the hypothesis), and we just confirmed $v \neq A[j]$, we now know that $v$ is not in $A[1..j]$.
        
    - Therefore, the invariant holds for the next iteration ($j+1$).
        

#### 3. Termination

**Goal:** What does the invariant tell us when the loop terminates?

- **Proof:** The loop terminates strictly when $j > A.length$ (specifically when $j = n + 1$).
    
- Substitute $n + 1$ for $j$ in our loop invariant: "The subarray $A[1..(n+1)-1]$ (which is $A[1..n]$) consists of elements not equal to $v$."
    
- This means we have proven $v$ is not present anywhere in the entire array.
    
- Therefore, the final step `return NIL` is correct.

### Critique of Your Solution

**1. The Pseudocode Logic Errors**

- **Direction of Loop:** You are looping `1 to n`. In binary numbers, the "Least Significant Bit" (the ones place) is usually at the end of the array (index $n$). You must add from **right to left** (from $n$ down to $1$), just like doing math on paper.
    
- **Missing the Carry in Sum:** You check `if A[j] + B[j] > 1`. What if `A[j]=0`, `B[j]=0`, but the previous column had a `carry=1`? Your code doesn't add the carry to the current sum.
    
- **The "Else" Logic:** You wrote `else C[j] = 1`. If $A[j]=0$ and $B[j]=0$, the sum is 0, not 1.
    

2. The Formal Statement

Your statement is readable but can be more mathematically precise by defining what the arrays actually represent.

### The Corrected Solution (CLRS Standard)

Here is how to formalize this properly.

#### 1. Formal Problem Statement

**Input:** Two arrays $A[1..n]$ and $B[1..n]$ of binary values (0 or 1), representing two integers $a$ and $b$ such that $a = \sum_{i=1}^{n} A[i] \cdot 2^{n-i}$ and $b = \sum_{i=1}^{n} B[i] \cdot 2^{n-i}$.

**Output:** An array $C[1..n+1]$ of binary values such that the integer $c$ represented by $C$ satisfies $c = a + b$.

#### 2. Pseudocode

We must loop backwards (from $n$ down to $1$). The current bit goes into $C[i+1]$ because $C$ is one element larger than $A$ and $B$.

Markdown

```
BINARY-ADD(A, B)
1.  carry = 0
2.  n = A.length
    // Loop from the last index (LSB) to the first (MSB)
3.  for i = n downto 1
4.      sum = A[i] + B[i] + carry
5.      C[i+1] = sum % 2     // The remainder is the bit value (0 or 1)
6.      carry = floor(sum / 2) // Integer division determines new carry
7.  C[1] = carry
8.  return C
```

---

### Loop Invariant (The "Next Step")

Since the logic changed, the invariant must change. We need to prove that after processing the last $k$ bits, the subarray of $C$ correctly represents the sum of the subarrays of $A$ and $B$.

Invariant Statement:

At the start of each iteration of the loop (for index $i$), the subarray $C[i+2..n+1]$ stores the sum of the $n-i$ least significant bits of $A$ and $B$ (specifically $A[i+1..n]$ and $B[i+1..n]$), plus the carry generated by position $i+1$.

**1. Initialization:**

- Before the first iteration ($i=n$), the subarray $C[n+2..n+1]$ is empty. The sum of zero bits is 0. The carry is 0. The invariant holds trivially.
    

**2. Maintenance:**

- In iteration $i$, we compute `sum = A[i] + B[i] + carry`.
    
- The logic places the correct bit ($sum \% 2$) into $C[i+1]$ (the current position in the output).
    
- The logic updates `carry` for the _next_ position ($i-1$).
    
- This effectively extends the correctness of the sum from the previous iteration by one more bit position to the left.
    

**3. Termination:**

- The loop terminates when $i=0$.
    
- The invariant states that $C[2..n+1]$ contains the sum of bits $A[1..n]$ and $B[1..n]$.
    
- Line 7 sets $C[1]$ to the final `carry`.
    
- Thus, $C[1..n+1]$ contains the complete correct binary sum.
